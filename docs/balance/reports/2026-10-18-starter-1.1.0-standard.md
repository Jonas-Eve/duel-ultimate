# Référence : `starter@1.1.0`, politiques `random` et `greedy`, règles par défaut (standard)

Instantané **daté** des effets d'options de règles de #127 (tâche T4 : #173, Epic #120). Les deux
sections rejouent **les mêmes graines moteur** : seule la politique change entre elles. La synthèse
et la lecture croisée des quatre combinaisons sont dans [`../rules-options.md`](../rules-options.md).

- **Date** : 2026-10-18
- **Commit** : `aa1fdbc` (`main` après #170, #171 et #172, binaire `--release` construit sur ce commit ;
  aucun code modifié par #173)
- **Graine** : `1` (écrite, et non `0`)
- **Règles** : `--hero-riposte on --board-limit 5`, explicites. Ce sont les valeurs de `RuleSet::standard()`, le défaut du moteur depuis #172 : le même lot **sans aucune option** donne exactement la même sortie (vérifié, comparaison octet pour octet).
- **Machine** : Intel Xeon 2,10 GHz, 4 coeurs (`nproc`), rustc 1.97.0 (2026-07-07), conteneur Linux
- **Commande** :

```
target/release/duel-simulator 2000 --set starter@1.1.0 --seed 1 --hero-riposte on --board-limit 5 --policy random,greedy
```

- **Vérifications** : code de sortie 0 ; lancée **deux fois**, sorties identiques octet pour octet ;
  durée d'environ 56 s en release (2 politiques x 3 matchups x 2000 parties), très en dessous du
  plafond de plausibilité de 10 minutes (voir `../throughput.md`).
